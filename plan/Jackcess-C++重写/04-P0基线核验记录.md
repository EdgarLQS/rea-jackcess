## 2026-11-20：C++ V2000 无索引表 overflow 行增长基线（初版）

以下结果记录行缩短实现之前的增长用例；当时缩短操作被拒绝。当前缩短实现和复测见下一节。

本地 C++ fixture 从固定模板新建 V2000 数据库，向无索引表写入 TEXT/BINARY 行，再依次把 TEXT 从 1 字符增长到 127、再增长到 255 字符，触发 inline-to-overflow 和 overflow-to-overflow 更新；随后执行等编码长度更新。CTest 另验证逻辑 RowId 与表行数不变、关闭重开后仍可读取，以及缩短更新被拒绝且文件字节不变。最终 fixture 大小为 110,592 字节，SHA-256 为 `9a9c0360e3c056ea286ca46c6c880b5c76f4497a065ac2f449a227483a47863b`。

固定 Jackcess 5.2.0 JAR 独立打开该 C++ 文件，检查预期 schema、4 行及重开后的最终值：255 个 `r` 字符、BINARY `{1,2,3}`、Unicode `🚀`、空值和 NULL。逻辑 RowId 稳定、行数保持、缩短拒绝且文件字节不变由定向 CTest 检查（`database_create` 为 1/1 通过）。此结果只验证合成 V2000 无索引表和受支持的单页行，不覆盖已有索引库写入、长值、Usage Map 扩展、其他格式或完整 P2 验收。

初版工具命令已随 fixture 增加缩短场景而过期；当前增长与缩短的可复现命令见下一节。此处哈希只标识初版运行产物。

## 2026-11-21：Jet4 索引叶分裂与两级索引树

上游 `IndexPageCache.splitDataPage`/`nestRootDataPage` 的布局约定（逐条核对后照做）：

- 节点条目尾部 8 字节 = 3 字节行页号 + 1 字节行号 + 4 字节大端子页号；节点条目的键是该子树**最大**键，命中搜索取"第一个键 ≥ 目标"的子页，超出则取最后一个子页。
- 根叶页不能就地分裂：先把全部条目搬到新页 N，根页降级为 level 1 节点并只放一个条目，然后再分裂 N。
- 分裂时把**前半**条目搬到新页并插在原页之前（`addToPeersBefore`），原页保留后半，因此原页在父页中的键仍然有效；前半页的父条目键 = 前半的最大键。
- 叶页链跨父页全局相连；节点页只在同一父页内相连。

C++ 实现（`src/write/jet4_index_entry.cpp` 重写为页树写入器）：

- 新增解析/序列化节点页与叶页、从根下降定位目标叶、按 `(key, row)` 二分定位插入点。
- 叶页满时（且调用方允许分裂）按 `(n+1)/2` 切分：新页放前半并接在原页之前，修补前后叶页的 prev/next，父页插入一条 `前半最大键 → 新页` 条目；根叶页走"新建 N + 根降级为节点"的路径。
- **额外修正**：节点键是子页最大键，因此叶子追加到超过旧最大值时必须刷新父条目，否则会出现两条相同键的节点条目、破坏严格升序。
- 新页同时登记到该索引自己的 Usage Map 行（`PhysicalIndexDefinition.owned_pages`）和全局页图，并按页号顺序追加到文件末尾。
- 更新/删除路径仍不允许追加页面：叶页满即拒绝；删除不合并叶页，删除非根叶页最后一条会拒绝（避免父键失效）；根叶页可以清空，等于新建索引的初始状态，因此可整表删空后重新插入。
- 批量插入改为**每个索引一次调用**（`apply_jet4_index_changes`）。此前逐条调用会每行重新从磁盘读页，导致同批次前面的条目被覆盖——这条缺陷在实现过程中被 700 行用例直接抓出。
- `src/index/index_cursor.cpp` 放宽节点页顺序校验为**非递减**：叶页仍是严格递增的 `(key,row)`，节点页键是子树最大键，重复键跨页时相邻节点键可以相等。

CTest `database_create` 新增 `test_index_split_and_multi_leaf_maintenance`：700 行批量插入后断言行数、页数增长、重开后 700 个键升序且去重键数为 700；随后删除第 350 与第 1 行、再插入 350/1/701，重开后 701 个键仍严格升序、去重键数为 701。全量 CTest 9/9 通过。

## 2026-11-21：删除时的叶页摘除与页面释放

此前删除某个非根叶页的最后一条会被拒绝（父条目携带子树最大键，空叶页会让它失效）。本轮实现"清空即摘除"：

- `TreeWriter::remove` 删除条目后，若叶页为空且不是根叶页，走 `drop_empty_leaf()`：修补前后叶页的 `prev`/`next` 把该页从叶链摘除；从父节点删掉指向它的条目；若父节点因此没有条目且它就是根页，根页退回为 `level 0` 的空叶页（等于新建索引的初始状态）。
- 被摘除的页通过 `Jet4IndexApplyResult::freed_pages` 返回，调用方把它同时从该索引的 Usage Map 行移除、并在全局页图里重新置为"空闲"（全局图 1 = 空闲，新增 `mark_global_pages_free`）。同一操作里多个索引释放的页合并成一次页 1 写入，避免后一次读盘覆盖前一次。
- 删除后若叶页非空但删掉的是最大键，父条目键同步下调，保持"父键 = 子树最大键"。
- 仍不做条目再分配（b-树经典的借位/半满合并），因此叶页只在**完全清空**时消失。

### 关系创建（`RelationshipBuilder` + `Database::create_relationship`）

入口在 `src/api/database.cpp`，Jet4 机制在 `src/write/jet4_relationship_creator.cpp`。写入顺序为：先向两端表的定义页追加逻辑索引描述（子表 `type=2`、`referenced_index_type=2` 指向父表别名；父表别名 `referenced_index_type=1` 回指子表索引），再向 `MSysRelationships` 按列对写目录行（`ccolumn` 为列对数，`icolumn` 为序号，`szObject`/`szColumn` 为子端，`szReferencedObject`/`szReferencedColumn` 为父端）。两端描述一次写盘，避免只写一侧导致后续写入的互指校验失败；目录行随后写入。不声明引用完整性的关系只写目录行并置 `dbRelationDontEnforce`。

定义页追加按既有布局做定点插入：`[header 63][每物理索引 12 字节行数块][列定义 25 字节][列名][物理索引块 52 字节][逻辑索引块 28 字节][索引名][长值映射][0xFF 0xFF]`。新描述块插在现有逻辑块之后、新名字追加在现有名字之后，并同步 `definition_size`、`logical_index_count` 和空闲空间字段；多页定义、页码不足、自引用、非 ASCII 关系名、端点为系统表或链接表均显式拒绝。

当前边界：父表参照列必须已有唯一索引，子表外键列必须已有索引（Jackcess 会自动建子端索引，本实现暂不建）；级联更新/级联删除/删除置空互斥与"级联需引用完整性"在创建时校验。创建后同一句柄的公开列/索引视图会重新读取两端定义，因此 `Table::indexes()` 立即反映新描述。

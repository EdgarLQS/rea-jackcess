# 只读错误分类与上下文

本文是[后续路线图 R5.1](12-只读后续实施路线图.md)的盘点结果：只读路径会报哪些 `DatabaseErrorCode`、各码在哪一层产生、调用方能依赖哪些上下文字段，以及仍未细分的分支。行为证据见[能力矩阵 EX-01](03-Jackcess-5.2.0能力矩阵.md)，接口签名见[接口契约](08-接口契约.md)。

## 1. 错误码语义

`DatabaseError` 由码、消息、文件路径、可选页号和可选上下文（表名、行号、列号、列名）组成。同一码在不同层出现时，上下文按"能确定多少填多少"补齐，不虚构。

| 码 | 含义 | 调用方可依赖 | 不用于 |
|---|---|---|---|
| `io_error` | 文件系统或流失败：路径不存在、无权限、seek/read/write 失败、CSV 目标无法打开 | `path()`（内存句柄为 `<memory>`，CSV 流操作为空） | 文件内容损坏或格式不支持 |
| `truncated_file` | 文件比头部短，或对齐后的页读取不足一页 | `path()`，页读取失败时另有 `page_number()` | 结构字段越界（那属于 `corrupted_file`） |
| `unsupported_version` | 引擎版本字节不在已识别集合，或某版本缺少对应布局实现 | `path()`，消息含实际版本值 | 已识别格式里的字段损坏 |
| `corrupted_file` | 已识别格式中的结构不一致：页类型、行目录、Usage Map、索引页、长值链、复杂列关联、文件长度与页大小不整除 | `path()`，尽量带 `page_number()` 与表/行/列上下文 | 调用方参数错误、功能未实现 |
| `page_out_of_range` | 请求的页号超出文件页数 | `path()`、`page_number()` | 页内结构越界 |
| `unsupported_operation` | 当前实现明确不做：ACE 读写、复杂列写入、CSV 导入复杂列、编码库缺 codec、未知复杂类型、不支持的代码页覆盖 | `path()`（按流操作时为空），能定位时带表/列上下文 | 文件损坏 |
| `constraint_violation` | 写入会破坏已声明约束：唯一键重复、外键悬空、列校验失败 | 表/列上下文，消息为调用方配置的 `ValidationText` | 只读路径的任何失败 |

## 3. 与固定 Jackcess 5.2.0 的对应

| Jackcess 异常 | 本项目码 | 说明 |
|---|---|---|
| `IOException`（读写失败） | `io_error` | 路径与系统消息保留 |
| `IOException`（"Empty database file" / 短读） | `truncated_file` | 按长度区分，不与损坏混用 |
| `IOException`（"Unsupported … version"） | `unsupported_version` | 保留版本字节 |
| `IOException`（结构不一致：页类型、行目录、Usage Map、长值链等） | `corrupted_file` | 保留页、表、列上下文 |
| `UnsupportedOperationException`（含 `UnsupportedCodecException`） | `unsupported_operation` | 缺 codec、编码库无处理器、功能未实现 |
| `IllegalStateException`（"invalid page number"） | `page_out_of_range` | 保留请求页号 |
| `InvalidValueException` | `constraint_violation` | 校验失败保留配置消息 |

本项目的码比 Jackcess 的异常层次更细，但不引入 Jackcess 没有的错误分支：细分只按"调用方能否分别处理"发生。

## 4. 已知缺口与刻意取舍

| 项 | 现状 | 处理 |
|---|---|---|
| CSV 流接口无路径 | `export_table_csv(Table&, std::ostream&)` 不知道来源，`io_error`/`unsupported_operation` 的 `path()` 为空，但表/列上下文齐全 | 保持；需要路径时调用文件接口 `export_table_csv(Table&, path)` |
| 待恢复日志 | 存在 `<库>.reajournal` 时只读打开报 `io_error`（"A previous write did not finish"） | 语义上更接近 `unsupported_operation`，但调用方目前按"文件暂不可读"处理，且该分支属于写路径验收范围，暂不改码以免破坏既有断言 |
| 错误分类未覆盖复杂值匹配 | `ColumnMatcher`/`ErrorHandler` 的自定义异常原样透传，不包装成 `DatabaseError` | 保持调用方异常语义；文档已声明回调异常不由库重写 |
| 加密库缺独立错误码 | 统一用 `unsupported_operation` | 暂无调用方需要区分"缺 codec"与"功能未实现"，若出现需求再增码 |
| 唯一键冲突的字段粒度 | `constraint_violation` 带表与列，但不指出冲突键值 | 键值可能含敏感数据，保持不填 |

## 5. 回归入口

| 入口 | 覆盖 |
|---|---|
| `error_context` | `io_error`（缺文件）、`truncated_file`（短文件与短缓冲、`<memory>` 路径）、`unsupported_version`（含版本值）、`corrupted_file`（文件长度不整除）、`page_out_of_range`（含页号）、`unsupported_operation`（ACE 读写、CSV 导入复杂列带表/列上下文） |
| `corrupt_read_*` | 截断副本、索引根/数据页损坏的 `page_out_of_range` 与 `corrupted_file`，含文件、页、表断言 |
| `long_value_corrupt` | 坏 MEMO 链的 `corrupted_file` 及文件、页、表、列、行上下文 |
| `page_codec` | 编码库缺处理器、工厂拒答、处理器异常的错误码与页号保留 |
| `csv_*` | 复杂列导入拒绝的表/列上下文 |

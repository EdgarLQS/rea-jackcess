# 验收与发布门槛

首期只读放行按[只读优先实施计划](09-只读优先实施计划.md)执行。Jet4 V2000/V2003 和 ACE V2007/V2010/V2016/V2019 各版本须完成只读矩阵、固定 Jackcess 对照及原生 Linux x86_64 和 ARM64 验证。后文格式矩阵与 P2–P5 中的写入和完整对齐要求用于长期验收。

## 1. 证据与比较规则

1. 按[计划总览](README.md)固定 Jackcess 5.2.0 源码和运行 JAR。记录候选构建提交、编译器、原生 Linux 发行版与架构、各对照工具版本、语料与预期产物 SHA-256。原始样本只读，修改操作使用独立副本。
2. 按[P0 初版能力矩阵](03-Jackcess-5.2.0能力矩阵.md)逐项登记格式、能力、上下文、操作、预期值或错误、用例、实际结果和产物。用例结论包含必过、明确拒绝或经评审的差异。未验证项保留证据缺口，阻止对应能力放行；初版矩阵审阅完成前不冻结 P0。
3. 复用 `$MDB_REFERENCE_DIR/resource/test-mdb-validation/` 中的 canonical JSON v1 与比较器。表按行多重集比较，BLOB 按长度和 SHA-256 比较。对系统表、索引遍历与引用、库表列属性、日期精度和关键浮点值增加独立断言，防止默认过滤、精度或容差掩盖差异。
4. 用手工预期明确的样本、固定版本 Jackcess 及可用的独立消费者交叉验证。历史 43 张共同表和公共语料 45/48 值一致用于选择及复核用例，候选实现按当前矩阵逐项给出证据。

## 2. 格式矩阵

下表是 P0 细化的初始边界。各格式的字段、元数据、公开 API、错误行为及特殊限制以 5.2.0 源码和实测冻结。

| 格式 | 读取已有库 | 创建新库 | 修改已有库 |
|---|---|---|---|
| Jet3（V1997） | 支持 | 拒绝 | 只读 |
| Generic Jet4 | 支持 | 拒绝 | 支持 |
| Jet4 V2000、V2003 | 支持 | 支持 | 支持 |
| ACE V2007、V2010、V2016、V2019 | 支持 | 支持 | 支持 |
| MSISAM 与有编码的 Jet/ACE | 识别格式，默认拒绝有编码的页读取 | 依基础格式的创建能力验收普通库，MSISAM 拒绝创建 | 默认拒绝有编码的页写入，支持配置 codec 扩展 |

只读打开的源文件在验收后必须保持哈希一致。Jet3 的只读行为和各格式不支持的操作均需有可复现的拒绝用例。自定义 codec 在独立样本上验证扩展契约。

## 3. 核心库关口

| 关口 | 必做验证 | 放行条件 |
|---|---|---|
| P0 · 基线 | 核验版本、样本来源及哈希，评审能力矩阵和三个难点的验证记录 | 有逐包估算和关键路径，各项能力能追溯到参考行为及用例 |
| P1 · Jet4 读取 | 原生 Linux 下按目录、schema、属性、索引定义和记录对照，覆盖迁移行、NULL、代码页与跨页长值 | 支持范围内无静默丢表、丢列或未解释的值差异 |
| P2 · Jet4 读写 | Java 建库或修改后由 C++ 读取；C++ 建库或修改后由 Java 读取。覆盖空表、多表、批插、更新删除、行迁移、长值和索引分裂 | 数据、元数据及页图和页链满足约定，索引查询与全表扫描结果一致，作为后续写入验收 |
| P3–P4 · 完整对齐 | 按格式执行双向互操作及负例，覆盖关系与级联、链接解析、查询定义、表达式、复杂列、OLE、工具及扩展点 | 所有承诺能力和拒绝行为均有通过的用例，差异具有评审记录 |
| P5 · 发布 | 原生 Linux x86_64 和 ARM64 全量回归；目标 Access 实机打开和查询；运行 ASan/UBSan、损坏文件、取消、并发及性能用例；审查最终产物依赖 | 矩阵必测项和实机互操作通过，达到 P0 约定的资源门槛，许可证和来源清单齐全 |

性能回归覆盖 200k 行、1 GB 数据和接近格式容量上限的用例，记录输入规模、实际读取或写入量、耗时和峰值 RSS。原生 CPU 环境单独登记，历史容器和模拟架构结果供参考。

故障注入覆盖页、长值和索引写入，模拟截断、短写、磁盘满及取消。新文件导出在发布前失败时，已有目标文件哈希保持一致，无目标时最终路径保持空缺。已有库操作在副本上核对约束预检结果、I/O 故障后的状态报告与停止写入行为。用独立解析或消费者验证页归属、页链和索引可达性。

## 4. PGeo 独立发布关口

| 能力 | 验收与放行 |
|---|---|
| 导入 | 通过目标 Linux 产品入口导入，与同源 MDB 的 GDAL PGeo 输出逐层比对，以图层和 OBJECTID 匹配要素，核查字段、类型、坐标、Z/M 和 SRS。缺失或未知 SRS 按明确规则提示。 |
| 样本克隆 | 生成新文件后由 GDAL 和目标 ArcGIS 工作流分别回读，对照图层、元数据、键集合、SHAPE 摘要和几何。同时验证空间索引记录与实际要素的关联及目标消费者的空间查询。 |

现有样本含 17 个图层和 30 个非空几何，图层 SRS 为空。两项能力各自补齐带有效 SRS 的样本、保存原始输入哈希和运行证据，通过对应关口后发布。

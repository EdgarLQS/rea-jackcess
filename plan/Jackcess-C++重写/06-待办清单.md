# 开发待办与长期工作包

当前执行顺序以[只读优先实施计划](09-只读优先实施计划.md)为准。从 W01 冻结首期只读矩阵与语料，执行 W02 的 Jet4 读取部分，然后执行 W05 的 ACE 读取部分。核心只读放行后独立启动 W13 的 PGeo 导入。写入与样本克隆后移，其余范围按首期矩阵排期。接手步骤见[只读优先开发交接](10-只读优先开发交接.md)。

以[能力矩阵](03-Jackcess-5.2.0能力矩阵.md)登记实现和证据，以[接口契约](08-接口契约.md)约束近期接口。W 编号用于开发任务，P 编号继续表示[实施阶段](01-实施工作包.md)。既有待办中的真实库阻塞项已形成若干通过测试的切片。P0 冻结和 P1/P2 放行见 [W01](#w01--基线和矩阵)与 [W02](#w02--jet4-读写工作包)。

从仓库根目录运行 `cmake -S . -B build && cmake --build build`。以下 CTest 命令接在构建后运行。新增功能进入已有测试组或增加有明确名称的用例，执行 `ctest --test-dir build -N` 核对已注册。Java 对照使用[固定 JAR 探针](04-P0基线核验记录.md)及其命令和数据生成步骤，先核验 JAR 哈希，记录输入、生成产物、命令、退出码、提交和平台。工具发现、缺样本或执行失败都留在矩阵中。

## 既有工作包 · 基线与 Jet4

### W01 · 基线和矩阵

首期先冻结六个目标版本的只读子矩阵。下列全表审查属于长期工作。

- **矩阵与依赖**：全表，以 REA 快照、固定 Jackcess 5.2.0 源码与 JAR 为前置。先用公开源码和上游测试查漏，再核查现有 C++ 测试的调用路径及边界。对同一测试组覆盖多个行为的情况记录具体断言。
- **验收**：运行 `ctest --test-dir build -N` 及 `ctest --test-dir build --output-on-failure`。逐行核对编号、责任工作包和证据；对缺失的源码/测试/语料标为待核实或未运行。为未完成包估算实现、语料、验证和外部等待，记录关键路径后提交 P0 冻结审查。

### W02 · Jet4 读写工作包

首期只读执行 V2000/V2003 的读取对照与回归。下列 Generic Jet4 探针、双向写入对照及写入维护任务按后续阶段安排。

- **矩阵与依赖**：DB-01、DB-02、DB-03、DB-05；TB-01、TB-02、TB-03；RW-01、RW-02、RW-03、RW-04、RW-05、RW-06、RW-07、RW-09、RW-10；IX-01、IX-02、IX-03、IX-04、IX-05、IX-06；RL-01、RL-02、RL-03；QA-01、QA-02。使用 W01 固定语料和版本。模块为 `api`、`catalog`、`index`、`value`、`write`、`page`。
- **开发顺序**：先补 Generic Jet4 的单独探针和两版真实既有库样本。再补复合 TEXT/MEMO 的前缀、唯一性与 NULL 对照，覆盖多级节点删除、重开和叶链可达性。复用[写入与索引契约](08-接口契约.md#写入与索引)。节点页再平衡单独验证，依据固定版行为及 P2 一致性要求判断是否纳入放行。
- **验收**：`ctest --test-dir build --output-on-failure -R 'database_create|catalog|cursor|foreign_key|relationship|index_merge|crash_recovery|multipage_definition|date_time|real_sample'`。对 V2000/V2003 分别做 Java→C++、C++→Java 双向回读。按行值、索引顺序和可达性、外键、长值摘要及失败后副本状态验收。在原生 Linux x86_64 和 ARM64 跑当期完整 CTest，并记录可选真实样本是否注册。未通过或缺证据的操作继续标为待验。

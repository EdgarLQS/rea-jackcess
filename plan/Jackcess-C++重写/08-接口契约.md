# 近期接口契约

签名来自 REA `81afd3d` 的[公开头文件](../../include/rea_jackcess/)。本文记录现有契约及下一步需要确认的边界。行为和证据状态以[能力矩阵](03-Jackcess-5.2.0能力矩阵.md)为准。待验证分支先用固定 Jackcess 5.2.0 探针核实，再调整契约与实现。

## 写入与索引

[W02](06-待办清单.md#w02--jet4-内部里程碑)，RW-01 至 RW-10、IX-01 至 IX-06、RL-01 至 RL-03。接口声明在 [table.hpp](../../include/rea_jackcess/table.hpp)。

```cpp
RowId add_row(const std::vector<Value>& values);
std::vector<RowId> add_rows(const std::vector<std::vector<Value>>& rows);
void update_row(RowId row_id, const std::vector<Value>& values);
void delete_row(RowId row_id);
void add_index(const IndexBuilder& index);
std::optional<Row> find_row_by_index(const std::string& index_name,
                                     const std::vector<Value>& key) const;
RowCursor rows_by_index_prefix(const std::string& index_name,
                               const std::vector<Value>& prefix,
                               bool reverse = false) const;
```

- 行写入要求显式读写打开且为支持的本地 Jet4 V2000/V2003 表。行值按列顺序输入，批量结果按输入顺序返回。行迁移后保留逻辑 RowId，支持的索引键与行在同一次操作维护。查找无匹配返回 `std::nullopt`，游标按索引顺序返回前缀命中行。未支持的键、索引或表形态显式拒绝。
- 调用方拥有输入容器与返回值。表及游标通过持有状态维持文件寿命。行标识从对应表取得。约束冲突用 `DatabaseErrorCode::constraint_violation` 报告，错误尽量带表、行和列。
- 失败验证使用副本。校验失败返回错误，已进入写盘的操作按现有回滚和日志语义处理。回滚自身失败时停止继续写入。进程中断后用读写打开执行恢复；存在待恢复日志时只读打开明确拒绝。
- 测试覆盖重复键、复合键字典序与前缀、NULL、行迁移、级联、目录与索引重开一致性。以 `database_create`、`cursor_v2000/v2003`、`foreign_key_v2000/v2003`、`crash_recovery_v2000/v2003` 为入口；扩展复合 TEXT/MEMO 和节点清理前先采集基线结果。

## 属性和校验

[W03](06-待办清单.md#第二优先级--补齐近期公开能力)，PR-01、PR-02、PR-03。见 [property.hpp](../../include/rea_jackcess/property.hpp)。

```cpp
// PropertyMapInfo
PropertyInfo& put(PropertyInfo property);
PropertyInfo& put(std::string name, Value value);
PropertyInfo& put(std::string name, std::uint8_t type_code, Value value,
                  bool is_ddl = false);
void put_all(const std::vector<PropertyInfo>& properties);
Value get_value(std::string_view property_name, Value default_value = {}) const;

// Database 和 Table
std::vector<PropertyMapInfo> property_maps() const;
void save_property_maps(const std::vector<PropertyMapInfo>& maps);
```

- 读取返回属性映射副本。通过 `put()` 或 `PropertyInfo::set_value()` 同步编码后再保存。保存使用记录的原始编码，未知属性通过原记录保留。调用方不得跨可能改变 `properties` 容器的操作长期保存元素引用。内建 DDL 标志、类型推导和缺省值沿用已有语义。
- 现有插入按「非空显式值优先，其余按支持的列默认值补齐 → 自定义列验证器 → 行编码、列与表规则、外键检查 → 写入」处理。当前插入路径会把缺省位置与显式 `std::monostate` 都作为默认值候选。更新使用自身的有效值路径。5.2.0 在显式 NULL、缺省输入及验证回调顺序上的差异分别用探针查证，兼容性结论以实测登记。
- 字面量和已支持规则按实际列类型校验。未支持的表达式明确拒绝。测试用固定 JAR 检查更新后属性、类型和 flags，并覆盖未知记录保留、NULL 保存及校验失败后的数据状态。现有入口为 `catalog` 和 `database_create`。

## ACE 复杂值读取

[W05](06-待办清单.md#第二优先级--补齐近期公开能力)，AC-01 至 AC-10。载荷类型见 [complex_value.hpp](../../include/rea_jackcess/complex_value.hpp)。

```cpp
std::vector<Row> raw_complex_values(std::string_view complex_column_name,
                                    RowId parent_row_id) const;
std::vector<ComplexValueInfo> complex_values(std::string_view complex_column_name,
                                             RowId parent_row_id) const;
```

- 在当前表内使用复合列名和父行 RowId。原始接口返回 flat table 匹配行，类型化接口返回拥有载荷的值。空关联键在可解析的关联结构下返回空集合。未知复合类型保留可读原始行与未识别字段字节。附件同时保留存储 wrapper 和解出的文件载荷。
- 当前无此列或列非复杂类型时抛 `std::invalid_argument`；行槽越界或已删除、关键关联结构缺失时存在带上下文的 `DatabaseError` 路径。异常 schema 各分支的精确错误分类、非标记 LONG 外键及跨表 RowId 拒绝行为由 W05 用固定版探针和测试确认。
- 已验证范围按矩阵中的 V2007、V2010 固定样本分别登记。用 `ace2007_read`、`ace2010_read`、`ace2007_unsupported_complex`、`attachment_value` 核对个数、顺序、类别和载荷。V2010/V2019 的计算列测试验证已存结果；求值属于 W11。附件流式接口属于 W09，复杂值写入属于 W07。

## 链接源

[W04](06-待办清单.md#第二优先级--补齐近期公开能力)，RL-04、RL-05。resolver 和快照类型见 [database.hpp](../../include/rea_jackcess/database.hpp)。

```cpp
Table open_linked_table(std::string_view name,
                        const LinkedTableResolver& resolver) const;
std::optional<Table> open_linked_table(
    std::string_view name, const LinkedTableResolver& file_resolver,
    const CustomLinkedSourceResolver& custom_resolver) const;
```

- 文件 resolver 返回调用方允许打开的路径。文件链接按来源数据库状态与存储的目标文件名缓存，支持显式解析多跳。自定义 resolver 返回共享源对象并惰性加载；空源指针允许文件回退，已识别源缺失目标表返回 `std::nullopt`。快照按表物化到临时库并继承来源读写模式。
- 结果 `Table` 保有目标状态；自定义源随相关表句柄保活。缓存和临时库共享阶段优先保持公开签名，先验证多表生命周期、并发加载及最后一个句柄释放。签名前置条件、回调异常、缺表和失败清理通过 `database_create` 链接用例及专项探针对照。

## 只读页 codec

[W09](06-待办清单.md#第二优先级--补齐近期公开能力)，DB-07。见 [page_codec.hpp](../../include/rea_jackcess/page_codec.hpp)。

```cpp
class PageCodec {
public:
    virtual void decode_page(std::uint8_t* page, std::size_t size, std::uint64_t page_number) = 0;
};

struct PageCodecContext {
    const FormatInfo& format;
    const std::filesystem::path& path;
    std::function<std::vector<std::uint8_t>(std::uint64_t)> read_raw_page;
    bool encoded;
};

using PageCodecFactory = std::function<std::shared_ptr<PageCodec>(const PageCodecContext&)>;

// DatabaseOptions
PageCodecFactory page_codec;
```

- 只覆盖读取方向。Access 只对页 1 及以后编码，页 0 始终原样返回，因此头部、编码键与 `DatabaseFile::is_encoded()` 在无 codec 时可读；codec 不会收到页 0。
- 工厂在每次打开时调用一次，早于任何目录页读取；句柄持有返回的 `PageCodec` 直到销毁，所有表、行、长值与索引读取共用同一实例。回调期间有效、回调后不保留 `PageCodecContext` 及其引用的对象。
- 页缓冲固定为一页（`FormatInfo::page_size`），原地解码，不允许改变大小或长期保有指针。`read_raw_page` 只返回存储字节，不进入 codec，供派生密钥使用。
- 返回空指针表示该库无需解码。库头声明非零编码键或容器为 MSISAM 时，空指针、缺工厂都以 `DatabaseErrorCode::unsupported_operation` 拒绝打开，不返回未解码的页。
- codec 抛 `DatabaseError` 时保留其码、路径与页号（页号为空才补当前页）；其他异常折为 `corrupted_file` 并补文件与页。`DatabaseFile::read_page` 明确返回存储字节，不解码。

## 后续模块边界

- `format` 决定版本布局及支持的操作；`page` 提供页访问、锁、日志和恢复。只读页 codec 与内存通道已按 5.2.0 的生命周期和错误语义定签名；写入方向的编码（加密库落盘）仍属后续工作包。
- `catalog` 管目录、结构和关联映射；`value` 管值和载荷编解码；`index` 管键和索引遍历；`write` 组合这些能力并维护一致性。ACE 写入先落普通行，再明确复杂值 ID、关联表、索引和失败恢复。OLE 流先验证字节访问和资源所有权。
- 表达式模块对值和求值上下文负责，供默认值、校验和计算列调用。通用 SQL 执行按额外能力立项。PGeo 适配通过核心公开接口取数据并在适配层调用 GDAL。

后续签名需有固定版本行为、错误语义和对应回归支撑。参见[源码架构](../../src/ARCHITECTURE.md)。

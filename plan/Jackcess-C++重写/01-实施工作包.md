# 实施工作包

## P0 · 冻结基线和工作量

1. 使用[计划总览](README.md#2-基线实施顺序与估算)中的 Jackcess 5.2.0 源码提交与 JAR。核对运行版本、哈希、测试样本、预期产物及工具版本。复用 `MDB_REFERENCE_DIR` 中的格式研究和比较器，为引用的资料和脚本记录来源及版本或哈希。
2. 按 5.2.0 的公开接口、构建器、工具、扩展点和对应测试建立能力清单。当前[能力矩阵](03-Jackcess-5.2.0能力矩阵.md)只完成 API/测试入口初盘，尚未冻结。继续审阅 5.2.0 测试，为各格式登记适用操作、读写与拒绝行为、错误语义、用例和证据；把页布局、编码和写入不变量对应到源码及样本。完成证据审阅后冻结初版矩阵，各包再继续补齐细节。
3. 优先验证三个难点。用索引语料对照排序键、分裂和查询顺序。用已有库副本验证行迁移、长值更新、键变化和删除。用 ACE 样本追踪附件、多值及历史记录等复杂列。记录每项工作量、未知项、前置和验证环境，据此提交完整首期估算及关键路径。
4. 确认原生 Linux x86_64、ARM64 的发行版和编译环境，登记目标 Access/ArcGIS 版本、客户工作流及耗时和 RSS 门槛。审查实现参考、空库模板、排序资源、样本与分发依赖的来源和许可。受限样本留在外部目录并按哈希引用。

## P1 · Jet4 读取

当前实施状态：已完成头识别、只读页 I/O、Jet4 表定义及 Usage Map 引用、数据页行目录、NULL/定长/变长字段读取、溢出行跟随，以及普通本地表 schema 和行发现。基础值解码覆盖布尔值、整数、浮点、短/扩展日期、Money/Numeric、文本、GUID、Binary 和 Memo/OLE 长值；负载原始字节会保留，无法表示的短日期 serial 输出 `$dateOutOfRange`。公开 `Database`、`Table`、`RowCursor`、`Row`、`RowId`、`Value` 提供 Jet4 只读访问，游标逐行按页读取；`Row::id()` 返回物理页号和行号。系统目录 `LvProp` 属性块已解析列 `Required` 布尔值，并用于公开 `ColumnInfo::nullable` 和 canonical schema；表定义中的物理索引列、标志、页引用，以及逻辑索引名称、主外键标记和关联信息已读取，公开 `Table::indexes()` 可访问逻辑索引定义。`src/index/` 已实现 Jet4 B-tree 页解析、根到最左叶页定位和叶链遍历，公开 `Table::rows_by_index()` 按索引顺序读取行；索引键语义解码、按键查找/范围游标和索引维护仍待实现。CLI `canonical` 输出 Jet4 canonical JSON v1 schema、列可空性、逻辑/物理索引定义、已支持值、行集哈希和文件元数据（源哈希、字节数、Jet 版本、代码页）。其他属性、构建器和写入仍待实现；属性块缺失、结构错误或不支持类型会记录在 `errors`。这不代表 P1 验收完成。

本机只读样本 `test_data_only_read/test_mdb.mdb`，SHA-256 `0bc0acb9c732de1e17c43c2d0a6019f7b5a62ccf83c5818a1bc42db7dbc460c6`，以 `./build/rea-jackcess inspect test_data_only_read/test_mdb.mdb` 对照 `mdb-export test_data_only_read/test_mdb.mdb MSysObjects`（MDBTools 1.0.1），系统目录 51 条记录的五个字段全量匹配；Jackcess 5.2.0 的 canonical 对照中 43 张共同用户表无 schema 或行值差异。导出原文未比较字段 `LvProp` 含 NUL 字节；比较解析时将 NUL 替换为哨兵字符，并对非 UTF-8 字节使用替换解码。合成测试覆盖内联 Usage Map、压缩文本、溢出行和 Jet4 基础值解码。样本不作为仓库测试资产，完整验收仍按[门槛](02-验收与发布门槛.md)执行。

当前本机对照可按以下命令复现（`MDB_REFERENCE_DIR` 指向计划总览说明的本地 MDB 参考目录）：

```sh
java -cp "$MDB_REFERENCE_DIR/resource/test-mdb/tools/jackcess/target/classes:$MDB_REFERENCE_DIR/resource/test-mdb/tools/jackcess/target/dependency/*" mdbprobe.JackcessDump --all --output /private/tmp/rea-jackcess-java-full.json --alias test_mdb.mdb test_data_only_read/test_mdb.mdb
./build/rea-jackcess canonical test_data_only_read/test_mdb.mdb > /private/tmp/rea-jackcess-canonical-full.json
python3 -I "$MDB_REFERENCE_DIR/resource/test-mdb-validation/compare.py" /private/tmp/rea-jackcess-java-full.json /private/tmp/rea-jackcess-canonical-full.json --out /private/tmp/rea-jackcess-java-full-compare.json
```

本次结果为 47 张表、328 行且无行读取失败；Jackcess 5.2.0 canonical 比较器报告 `common=43 only_ref=0 only_cand=0 mismatched=0`。列 `Required` 属性读取后，该样本 canonical 无错误。独立 Jackcess 5.2.0 `Table.getIndexes()` 对照中，138 个用户逻辑索引的名称、唯一性、Required/IgnoreNulls、主外键标记、列和方向均匹配，差异为 0；C++ canonical 共读到 145 个逻辑索引和 142 个物理索引，额外 7 个逻辑项来自该 Java dumper 默认不枚举的系统表。reference dump 将 `nullable` 固定输出为 null，因此该字段单独通过属性映射规则和合成块测试验证。

索引行序列的独立对照使用仓库内 `tools/validation/index_order_dump.cpp` 和 `tools/validation/JackcessIndexOrderDump.java`，分别通过公开 C++ API 和固定 Jackcess 5.2.0 的 `IndexCursor` 输出每个用户索引的行页号/行号序列。输入样本 SHA-256 为 `0bc0acb9c732de1e17c43c2d0a6019f7b5a62ccf83c5818a1bc42db7dbc460c6`，Jackcess JAR SHA-256 见本计划基线。复现命令：

```sh
c++ -std=c++17 -Iinclude tools/validation/index_order_dump.cpp build/librea_jackcess.a -o /private/tmp/rea-index-order-dump
javac -cp "$MDB_REFERENCE_DIR/resource/test-mdb/tools/jackcess/target/dependency/*" -d /private/tmp tools/validation/JackcessIndexOrderDump.java
/private/tmp/rea-index-order-dump test_data_only_read/test_mdb.mdb > /private/tmp/rea-index-order.txt
java -cp "/private/tmp:$MDB_REFERENCE_DIR/resource/test-mdb/tools/jackcess/target/dependency/*" JackcessIndexOrderDump test_data_only_read/test_mdb.mdb > /private/tmp/jackcess-index-order.txt
diff -u /private/tmp/jackcess-index-order.txt /private/tmp/rea-index-order.txt
```

本次两侧各输出 138 个用户逻辑索引，所有索引的完整 `page:row` 序列一致，`diff -u` 返回 0。该样本对照仅验证此 Jet4 样本，不替代 P1 格式矩阵验收。

1. 以 C++17、CMake 建立核心库、验证 CLI 和测试入口。核心内部分为页 I/O、格式布局、目录和表、值、属性和索引、写入。公开只读核心接口现提供 RAII `Database`、`Table`、`RowCursor`、`Row`、`RowId`、`Value` 和带上下文错误；写入构建器与属性/索引接口随后按工作包补齐。诊断 CLI 输出 canonical JSON v1，供对照工具消费。
2. 实现 Jet4 文件头识别、有界随机页 I/O 和只读访问。读取系统目录、跨页表定义、Usage Map、行目录、删除标记与迁移行。校验页号、算术溢出、短读和循环引用，错误按可得信息定位文件、页、表、行及列。
3. 解码定长、变长、NULL 位图、压缩文本、数值精度、日期、GUID、二进制与 Memo/OLE 长值。支持有界读取多页长值，保留原始字节。读取列 `Required` 属性并推导可空性，读取逻辑/物理索引定义；Jet4 B-tree 叶链顺序扫描已实现，继续补齐库/表/其他列属性、键语义解码、按键查找和范围游标。先验收 V2000，再加入 V2003 和 Generic Jet4。

## P2 · Jet4 写入与已有库修改

1. 验证可用的 V2000、V2003 空库模板。模板无法核准时，根据已验证的布局生成引导页并重估。实现文件与 Usage Map 页分配，写入系统目录、跨页表定义、表列属性及索引。按空表、单表、多表逐步用 Java 回读。
2. 实现批量插入以及已有库的行更新和删除。处理行变长迁移、长值链、索引键变化和页归属。实现该格式适用的表结构变更、AutoNumber、主键和唯一索引。用 Jet4 排序编码验证升降序、空键、重复键、页分裂与删除后的可达性。
3. 单文件采用单写者模式，验证打开模式、刷新与关闭。已有库操作在样本副本上验证，在可预检的约束失败后核对文件状态，页 I/O 失败时报告错误、标记当前写入状态并停止后续修改。
4. 产品新文件导出写入同目录临时文件，完成刷新、关闭和独立回读后原子发布。取消和超时由调用层管理。Jet4 读写通过后形成第一个内部里程碑。

## P3 · 其他格式与索引行为

1. 复用核心 I/O 和逻辑层，按布局分别实现 Jet3 和 ACE 各版本。核对页和行布局、系统目录、字符和排序编码、扩展字段、长值和格式限制。按 [格式矩阵](02-验收与发布门槛.md#2-格式矩阵)验证创建、打开、读取、修改和拒绝。
2. 补齐对应格式支持的索引查询与范围游标、复合键、排序变体和不支持的排序规则行为。验证键编码、键到行的映射、分裂、删除及重新打开结果。
3. 识别 MSISAM 及有编码的 Jet/ACE 文件。提供等价的 codec 配置和页编解码扩展点，默认按参考版本拒绝相关读写操作。用确定性的测试 handler 验证调用顺序和错误传播。

## P4 · 公开能力对齐

1. 完成关系发现、创建及约束执行，覆盖外键和级联行为。实现链接表元数据与解析扩展接口，默认要求调用方显式配置解析器。支持保存查询定义的读取和 SQL 表达。
2. 对照可用格式实现复杂列，包括附件、多值、历史记录及对应的读写边界。实现默认值、校验与计算列所用的表达式行为，按参考测试核对类型转换、时间、区域与错误语义。
3. 完成 OLE 封装、公开构建器与属性 API、游标和行过滤、导入导出工具、文件通道及错误处理等矩阵条目。验证适用版本和扩展点的行为。便捷接口复用核心读写能力。

## P5 · 核心库验收与产品接入

1. 在两种原生 Linux 架构持续进行差异回归、sanitizer、压测和错误注入。按 [验收门槛](02-验收与发布门槛.md)汇总从格式支持到公开 API 的证据，完成 Access 互操作。
2. 交付核心库、验证 CLI、兼容矩阵及第三方来源清单。核对实际核心产物的传递依赖，核心库以原生方式运行，Java、libmdb、GDAL 作为验证或适配依赖分别管理。产品接入时验证入口、取消、错误映射和失败清理，保留已验证的产品回退路径。

## P6 · PGeo 导入和样本克隆

1. 导入从目录发现图层，经核心读取属性、OBJECTID、SRS 元数据和原始 SHAPE 字节。固定版本 GDAL 解码几何，核对单多部件、坐标和 Z/M，明确报告缺失或无法解析的 SRS。
2. 克隆利用 C++ 写入器复制已验收样本的结构、元数据、原始 BLOB 和空间索引相关表，保留对象编号和关联。按支持清单验证索引记录与实际要素的一致性。导入与克隆通过各自的验收门槛后分别发布。

## 上游版本同步

1. 在仓库 CI 中每日检查一次官方稳定版本标签，并提供手动触发。跟踪 `spannm/jackcess` 的 `jackcess-X.Y.Z` 标签和解析后的源码提交。CI 摘要列出高于当前基线的稳定版本，报告提交、公开 API、格式及索引逻辑、测试和资源差异。检查失败时报告原因，保留上一次成功结果和时间。
2. 新版本在下一次成功检查中发现。维护者在两个工作日内完成差异分级并登记同步任务，优先处理数据正确性和兼容性修复。任务关联受影响的矩阵条目和相应回归。
3. 用常规评审提交更新源码提交、JAR 哈希、能力矩阵、样本以及所需实现。新增用例与原兼容回归均通过后切换基线。首期以 5.2.0 验收，后续稳定版本按此流程同步。

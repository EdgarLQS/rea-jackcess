# 实施工作包

## P0 · 冻结基线和工作量

1. 使用[计划总览](README.md#2-基线实施顺序与估算)中的 Jackcess 5.2.0 源码提交与 JAR。核对运行版本、哈希、测试样本、预期产物及工具版本。复用 `MDB_REFERENCE_DIR` 中的格式研究和比较器，为引用的资料和脚本记录来源及版本或哈希。
2. 按 5.2.0 的公开接口、构建器、工具、扩展点和对应测试建立能力清单。当前[能力矩阵](03-Jackcess-5.2.0能力矩阵.md)只完成 API/测试入口初盘，尚未冻结。继续审阅 5.2.0 测试，为各格式登记适用操作、读写与拒绝行为、错误语义、用例和证据；把页布局、编码和写入不变量对应到源码及样本。完成证据审阅后冻结初版矩阵，各包再继续补齐细节。
3. 优先验证三个难点。用索引语料对照排序键、分裂和查询顺序。用已有库副本验证行迁移、长值更新、键变化和删除。用 ACE 样本追踪附件、多值及历史记录等复杂列。记录每项工作量、未知项、前置和验证环境，据此提交完整首期估算及关键路径。
4. 确认原生 Linux x86_64、ARM64 的发行版和编译环境，登记目标 Access/ArcGIS 版本、客户工作流及耗时和 RSS 门槛。审查实现参考、空库模板、排序资源、样本与分发依赖的来源和许可。受限样本留在外部目录并按哈希引用。

## P1 · Jet4 读取

当前实施状态：已完成头识别、只读页 I/O、Jet4 表定义及 Usage Map 引用、数据页行目录、NULL/定长/变长字段读取、溢出行跟随，以及普通本地表 schema 和行发现。基础值解码覆盖布尔值、整数、浮点、短/扩展日期、Money/Numeric、文本、GUID、Binary 和 Memo/OLE 长值；负载原始字节会保留，无法表示的短日期 serial 输出 `$dateOutOfRange`。公开 `Database`、`Table`、`RowCursor`、`Row`、`RowId`、`Value` 提供 Jet4 只读访问，游标逐行按页读取；`Row::id()` 返回物理页号和行号。系统目录 `LvProp` 属性块已解析列 `Required` 布尔值，并用于公开 `ColumnInfo::nullable` 和 canonical schema；表定义中的物理索引列、标志、页引用，以及逻辑索引名称、主外键标记和关联信息已读取，公开 `Table::indexes()` 可访问逻辑索引定义。`src/index/` 已实现 Jet4 B-tree 页解析、根到最左叶页定位和叶链遍历，公开 `Table::rows_by_index()` 按索引顺序读取行；索引键语义解码、按键查找/范围游标和索引维护仍待实现。`src/page/PageFileWriter` 另提供既有 Jet4 文件的内部整页覆盖、追加和刷新，不属于已验收的数据库语义写入。CLI `canonical` 输出 Jet4 canonical JSON v1 schema、列可空性、逻辑/物理索引定义、已支持值、行集哈希和文件元数据（源哈希、字节数、Jet 版本、代码页）。其他属性、构建器和写入仍待实现；属性块缺失、结构错误或不支持类型会记录在 `errors`。这不代表 P1 验收完成。

## P2 · Jet4 写入与已有库修改

当前实施状态：`Database::create` 已支持以 Jackcess 5.2.0 官方空库模板创建 V2000/V2003 文件；新增重载可在 V2000 新库中创建一个或多个空表，当前支持 BYTE、SHORT、LONG、SINGLE、DOUBLE、TEXT、BINARY 列且完整表定义须能放入一个 4 KB 页。TEXT 默认容量为 255 个 UTF-16 字符，BINARY 为 255 字节；表名和列名限 1–64 个 ASCII 字母、数字、空格和下划线。写入器追加单页表定义和 Usage Map 页，在现有 `MSysObjects` 数据页中新增目录行，更新 `Id`、`ParentIdName` 两个系统索引叶页及对应目录计数，并清除全局内联 Usage Map 对应的页可用位；超过该页图范围暂时拒绝。C++ 回读会在原子发布前核对表名、列名、类型和空行集。新增 3. 识别 MSISAM 及有编码的 Jet/ACE 文件。提供等价的 codec 配置和页编解码扩展点，默认按参考版本拒绝相关读写操作。用确定性的测试 handler 验证调用顺序和错误传播。

## P4 · 公开能力对齐

1. 完成关系发现、创建及约束执行，覆盖外键和级联行为。实现链接表元数据与解析扩展接口，默认要求调用方显式配置解析器。支持保存查询定义的读取和 SQL 表达。
2. 对照可用格式实现复杂列，包括附件、多值、历史记录及对应的读写边界。实现默认值、校验与计算列所用的表达式行为，按参考测试核对类型转换、时间、区域与错误语义。
3. 完成 OLE 封装、公开构建器与属性 API、游标和行过滤、导入导出工具、文件通道及错误处理等矩阵条目。验证适用版本和扩展点的行为。便捷接口复用核心读写能力。

## P5 · 核心库验收与产品接入

1. 在两种原生 Linux 架构持续进行差异回归、sanitizer、压测和错误注入。按 [验收门槛](02-验收与发布门槛.md)汇总从格式支持到公开 API 的证据，完成 Access 互操作。
2. 交付核心库、验证 CLI、兼容矩阵及第三方来源清单。核对实际核心产物的传递依赖，核心库以原生方式运行，Java、libmdb、GDAL 作为验证或适配依赖分别管理。产品接入时验证入口、取消、错误映射和失败清理，保留已验证的产品回退路径。

## P6 · PGeo 导入和样本克隆

1. 导入从目录发现图层，经核心读取属性、OBJECTID、SRS 元数据和原始 SHAPE 字节。固定版本 GDAL 解码几何，核对单多部件、坐标和 Z/M，明确报告缺失或无法解析的 SRS。
2. 克隆利用 C++ 写入器复制已验收样本的结构、元数据、原始 BLOB 和空间索引相关表，保留对象编号和关联。按支持清单验证索引记录与实际要素的一致性。导入与克隆通过各自的验收门槛后分别发布。

## 上游版本同步

1. 在仓库 CI 中每日检查一次官方稳定版本标签，并提供手动触发。跟踪 `spannm/jackcess` 的 `jackcess-X.Y.Z` 标签和解析后的源码提交。CI 摘要列出高于当前基线的稳定版本，报告提交、公开 API、格式及索引逻辑、测试和资源差异。检查失败时报告原因，保留上一次成功结果和时间。
2. 新版本在下一次成功检查中发现。维护者在两个工作日内完成差异分级并登记同步任务，优先处理数据正确性和兼容性修复。任务关联受影响的矩阵条目和相应回归。
3. 用常规评审提交更新源码提交、JAR 哈希、能力矩阵、样本以及所需实现。新增用例与原兼容回归均通过后切换基线。首期以 5.2.0 验收，后续稳定版本按此流程同步。

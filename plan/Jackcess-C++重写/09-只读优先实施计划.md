# 只读优先实施计划

## 目标与边界

首个核心库里程碑是在原生 Linux x86_64 和 ARM64 上交付普通、未编码数据库的只读能力。先验收 Jet4 V2000/V2003，再逐版本验收 ACE V2007/V2010/V2016/V2019。行为以[固定 Jackcess 5.2.0 源码和 JAR](README.md#2-基线实施顺序与估算)为准。

复用现有数据库、表、游标、类型化值和验证 CLI。首期覆盖本地表目录、表列定义、行与投影、长值、属性、关系、保存查询定义及适用的索引读取和按键查询。ACE 补充适用的复杂值和计算列已存结果读取。按版本登记明确支持及拒绝的行为。

Jet3、Generic Jet4、MSISAM、编码或加密库、外部链接源解析、通用 OLE 流式接口和表达式求值列入后续工作。暂停新增写入能力，继续运行已有写入回归。核心只读放行后独立推进 PGeo 导入，样本克隆随写入工作后移。

## 实施顺序

| 顺序 | 工作包 | 交付与退出条件 |
|---|---|---|
| 1 | 冻结首期只读矩阵和语料 | 从现有[能力矩阵](03-Jackcess-5.2.0能力矩阵.md)提取六个目标版本的读取项。逐项登记格式、入口、预期结果或错误、语料来源和 SHA-256、对照脚本及证据。优先落实独立来源 Jet4、V2016、额外 V2019 语料及两种原生 Linux 环境。按剩余缺口重估各工作包和关键路径。 |
| 2 | 收口 Jet4 V2000/V2003 | 分版本对照目录、表列、行值、库表列属性、关系、保存查询定义、索引遍历、精确查找和区间边界。补独立语料中的 NULL、非 ASCII 文本、迁移行、跨页长值和复合索引。通过该阶段全部必测项后给出 Jet4 阶段结论。 |
| 3 | 收口 ACE | 先扩展 V2007/V2010 固定样本的逐字段对照，再覆盖 V2016 普通表及 V2019 扩展语料。核对适用版本的复杂列关联键、多值、附件摘要、版本历史及未知类型原始字节。用独立样本确认非标记 LONG 外键回退，补异常关联用例。复现并处理 V2019 固定样本中已记录的 `MSysResources.Data` 类型映射缺口。计算列只验证已存值和逻辑类型。 |
| 4 | 核心只读放行 | 两种原生 Linux 架构各自完成校验并保存证据。版本或能力存在缺样、未验证行为或未解释差异时，保留缺口并阻止对应项放行。 |
| 5 | 独立推进 PGeo 导入 | 通过目标 Linux 产品入口，与同源 MDB 的 GDAL PGeo 输出逐层对照字段、OBJECTID、几何、Z/M 和 SRS，补齐带有效 SRS 的样本。 |

## 验证和交付证据

- 普通数据复用 canonical JSON v1 和固定 Jackcess 5.2.0，逐表比较 schema 和行多重集，BLOB 比较长度和 SHA-256。对系统表、索引顺序及边界、属性、日期精度、复杂关联和附件载荷补独立断言。
- 运行全量 CTest 和 ASan/UBSan。覆盖默认及显式只读打开、未完成写入日志拒绝、ACE 读写打开拒绝、截断、无效页引用、坏长值链及坏复杂关联。核对原始文件操作前后哈希与旁文件，确认只读打开不会触发写入恢复。
- 分别记录两种原生 Linux 的提交、编译器、工具版本、语料哈希、命令、结果及差异。覆盖现有验收门槛中的 20 万行、1 GB 性能场景，记录耗时和峰值 RSS，冻结矩阵时确定资源门槛。核查核心产物运行时依赖，JVM、libmdb、GDAL 仅用于外部验证或独立适配。
- 继续使用[验收与发布门槛](02-验收与发布门槛.md)的证据规则。实现、固定样本对照、本机回归和目标平台验收分别登记。

接手入口见[只读优先开发交接](10-只读优先开发交接.md)。

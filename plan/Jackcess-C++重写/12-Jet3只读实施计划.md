# Jet3（V1997）只读实施计划

首期只读范围不含 Jet3，本文件记录启动 Jet3 只读的第一阶段成果、已核对的格式事实和后续拆分。
行为基线仍是固定 Jackcess 5.2.0（读 Jet3 只用读路径，该版本对 V1997 明确只读）。

## 1. 语料

Jackcess 5.2.0 的仓库自带 9 份 V1997 测试库，本机位于
`~/Documents/GitHub/jackcess/src/test/resources/data/V1997/`（Apache License 2.0 测试数据，不入本仓库）。

| 文件 | 用途 |
|---|---|
| `common1V1997.mdb` | 4 张表，`Table1` 9 列 2 行，其余表行数为 0 |
| `common2V1997.mdb` | 第二种常见结构 |
| `compIndexV1997.mdb`、`indexV1997.mdb`、`indexCodesV1997.mdb` | 复合索引、索引、编码索引 |
| `overflowV1997.mdb` | 行溢出 |
| `delV1997.mdb`、`delColV1997.mdb` | 删除行、删除列 |
| `queryV1997.mdb` | 保存查询 |

`tests/CMakeLists.txt` 用缓存变量 `REA_JACKCESS_JET3_DIR` 指向该目录（默认上表路径）；目录不存在时
`jet3_read` 不注册，CI 上因此不会执行 Jet3 用例。

## 2. 已核对的格式事实

以下数字取自固定 Jackcess 5.2.0 的 `JetFormat.Jet3Format`，可直接作为实现依据：

| 项 | Jet3 值 |
|---|---|
| 页大小 | 2048 |
| 单行上限 | 2012 字节 |
| 最大库大小 | 1 GB |
| 数据页初始空余 | `PAGE_SIZE - 14` |
| 表定义页续页指针 | 4 |
| 表定义行数 / 下一自增 / 表类型 | 20 / 20 / 21 |
| 最大列数 | 21 |
| 变长列数 | 23 |
| 列数 | 25 |
| 索引槽数 / 索引数 | 27 / 31 |
| 拥有页 / 空闲页 Usage Map | 35 / 39 |
| 索引定义块起点 | 43 |
| 索引列块大小 | 39 |
| 头部掩码 | 去掉最后 2 字节（Jet4 用完整掩码） |
| 排序序 / 代码页偏移 | 58 / 60 |
| 密码偏移与长度 | 66 / 20 |
| 索引支持 | 支持读取 |
| 写入 | Jackcess 5.2.0 对 V1997 明确只读 |

与 Jet4 的关键差异（实现时必须处理）：

1. **文本编码**：Jet3 用代码页（样本为 1252），不是 UTF-16LE；表中文本按列排序序或库代码页解码。
2. **表定义布局**：TDEF 头、索引定义块、列定义块的偏移和大小都与 Jet4 不同，需按上表参数化。
3. **行布局**：Jet3 行头与 NULL 掩码的位置、定长区起点与 Jet4 不同，需按 `format` 分支解码。
4. **索引键编码**：Jet3 索引键按代码页文本排序，截断长度与 Jet4 的 255 UTF-16 单元不同。

## 3. 当前实现状态（J1 + J2 定义解析）

- `DatabaseFile::open` 能识别 Jet3：`EngineVersion::jet3`、`FileFormat::v1997`、页大小 2048、只读标志。
- `Database::open` / `Database::tables()` 仍以 `unsupported_version` 拒绝，错误带文件路径和
  "unsupported engine version" 说明。
- `tests/jet3_read_test.cpp`（`jet3_read`）固定上述边界：版本、页大小、只读标志、页数大于 2、
  明确拒绝的码与消息，以及打开前后样本字节不变。
- `src/catalog/jet3_table_definition.cpp` 已能解析 Jet3 表定义页：头部 43 字节、索引定义 8 字节/个、
  列头 18 字节、1 字节名称长度、代码页文本；续页按页首 4 字节链拼接并跳过 8 字节头。
  `jet3_table_definition` 用例验证 `Table1`（9 列 A–I，长度 50/100/1/2/4/8/8/8/1，2 行）、
  `MSysObjects`（17 列、22 行）与跨两页的 89 列宽表。
- J3 已落地：数据页头部（行数偏移 8、行目录偏移 10）、行头 1 字节列数、NULL 掩码在行尾、
  定长区从行首 +1 开始、变长列用 1 字节偏移加 256 步进跳转表；值解码复用 Jet4 的数值/日期/
  GUID/二进制/OLE/MEMO 容器，仅文本走代码页。`jet3_read` 现在断言 10 张表（含 4 张用户表）与
  `Table1` 两行的每个值。
- 用固定 JAR 全表对照：`common1V1997`、`overflowV1997`、`indexV1997`、`compIndexV1997`、
  `delV1997` 的 schema 与行多重集全部一致；`common2V1997` 仅 `PROJ_OPT_CURRENCY_SYMBOL`
  一个单元格不同（见下）。
- 索引定义与索引游标尚未接入，`MSysQueries` 的 SQL 重建也未验证。

这一阶段刻意不返回空表清单：空表会让调用方误以为库中没有表，显式拒绝更符合现有
`catalog` 契约。

## 4. 后续拆分

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| J2 表定义 | 按上表参数化 TDEF 解析，读取列名/类型/长度/序号与逻辑索引定义 | 列定义已通过 `jet3_table_definition`；待 J3 行解码后由 `tables()` 返回 4 张表，索引留给 J4 |
| J3 行与值 | Jet3 行头、NULL 掩码、定长/变长区；代码页文本解码；Memo/OLE 长值 | `Table::rows()` 与固定 JAR 逐值一致（`Table1` 2 行 9 列）；`common2`、`overflow` 样本通过 |
| J4 索引与查询 | Jet3 索引定义、索引游标；保存查询定义 | 索引：`jet3_index_read` 通过；查询：`jet3_query_read` 通过，9 条 SQL 与固定 JAR 完全一致 |

每阶段沿用现有工具：C++ 侧 `rea-jackcess canonical`，Java 侧 `tools/validation/JackcessTableDump.java`
（对 Jet3 同样可用），比较器 `tools/validation/compare_table_dump.py`。

## 4.1 J4 索引阶段（已实现）

索引定义与索引游标已落地：物理索引块 39 字节（块内 10 组 `(u16 columnNumber, u8 flags)`、4 字节
Usage Map、+34 根页、+38 标志）、逻辑索引块 20 字节、索引名 1 字节长度 + 代码页文本；索引页头按
版本参数化（prev 8 / next 12 / child tail 16 / 压缩字节数 20 / 条目掩码 22 × 226 / 无 level，
条目数据从 248 开始，用页类型区分叶与节）。

`jet3_index_read` 在 `indexV1997.mdb` 上断言：`Table1` 的四个索引名、`PrimaryKey` 的唯一/主键标志与
根页 40、主键正序 `0,1,2,3`、反序与按键查找，打开前后样本字节不变。固定 JAR 的索引游标给出同样顺序。

### 4.1.1 保存查询（已实现）

Jet3 的 `MSysQueries` 只有 7 列（`ObjectId`、`Attribute`、`Order`、`Name1`、`Name2`、
`Expression`、`Flag`），没有 Jet4 的 `LvExtra`。查询读取改为：`LvExtra` 缺失时按空值处理，
字段解码走版本分发（Jet3 文本按代码页）。

`jet3_query_read` 在 `queryV1997.mdb` 上断言 9 条查询的名称与顺序，并逐字符比对
`UnionQuery`、`DeleteQuery`、`UpdateQuery`、`SelectQuery` 的 SQL；其余 5 条断言 SQL 非空。
与固定 JAR 的 `toSQLString()` 逐条比对，**9 条全部完全一致**。

下列常量是上一轮试探的原始记录，保留以备查：

| 项 | Jet3 值 | 来源 |
|---|---|---|
| 索引定义块尺寸 | 39 字节/个，紧跟列名之后，跨步实测一致 | `indexV1997.mdb` 9 张含索引的表 |
| 物理索引根页 | 块内 +34（4 字节小端） | 同上，9 处命中且页类型均为索引叶 |
| 唯一键数 | TDEF 索引定义块 +4，与 Jet4 相同 | `IndexData.create` |
| 索引页 prev / next | 8 / 12 | `JetFormat.Jet3Format` |
| 子页尾指针 | 16 | 同上 |
| 压缩字节数 | 20 | 同上 |
| 条目掩码偏移 / 长度 | 22 / 226 | 同上 |
| 层级字段 | 无（`offsetIndexLevel = -1`） | 同上 |
| 条目数据起点 | 22 + 226 = 248 | 推导 |
| 逻辑索引信息块 | 20 字节/个 | `SIZE_INDEX_INFO_BLOCK` |

仍未定：块内列描述字段的起点。Jet4 用 `block+4` 起的 `(u16 columnNumber, u8 flags)` 三元组；Jet3 的样本字节更像从 `block+0` 起每 3 字节一组（首例解出列号 3/5/7，随后是 `0xffff` 填充），需要对照 `IndexImpl` 源码再确认。逻辑索引信息块 20 字节的字段含义同样待核。

## 4.2 已知差异

`common2V1997.mdb` 的 `MSP_PROJECTS.PROJ_OPT_CURRENCY_SYMBOL` 存有字节 `0xA3`。固定 JAR 用
`Charset.defaultCharset()`（JVM 默认 UTF-8）解码，得到替换字符 U+FFFD；本实现按文件代码页
Windows-1252 解码为 `£`。这是 Jackcess 5.2.0 的本地化缺陷，本实现选择按代码页解释，差异已登记，
不作为缺陷修复。

## 5. 覆盖边界

- 代码页实现 1252（样本代码页）、819/28591（Latin-1）、1251、936（GBK）与 932（Shift-JIS）。
  DBCS 映射表由 `tools/validation/JackcessCharsetTableGen.java` 从 Java NIO 字符集（即固定 J 实际
  使用的解码器）生成到 `src/util/code_page_*.inc`，非法序列的替换语义（每次坏序列一个 U+FFFD、
  0xFF 吞掉整对等）已对 Java 逐字节核验；1251 与 936 另与 Python 的 gbk/cp1251 编解码器交叉核对：
  21,790 个已定义双字节全部一致，2,148 个 Java 专属用户区映射已记录，Java 与 Python 在 A2E3、
  A892 两处的既有分歧保留 Java 值。936 与 932 共用 `decode_dbcs` 模板（各自单字节表、双字节表与
  前导字节行映射）。端到端对照已做：`tools/validation/make_jet3_936_sample.py` 与
  `make_jet3_932_sample.py` 分别把 `common1V1997.mdb` 副本中两个 ASCII 单元改成等长 GBK / Shift-JIS
  字节（中文数g、数据库测p / テストg、日本語测p），`canonical --code-page 936|932` 与固定 JAR
  `JackcessTableDump … GBK|windows-31J` 的 10 张表逐表一致。真实 Access 生成的 936 / 932 库仍缺语料。
- 用例只在 `common1`、`index`、`query` 三份样本上做了断言；其余样本（`common2`、`overflow`、
  `compIndex`、`indexCodes`、`del`）用 `canonical` + 固定 JAR 做过全表对照，但没有进 CTest。
- CI 已覆盖 Jet3：`.github/scripts/ci.sh` 下载固定哈希的上游 5.2.0 源码包
  （`d1ba0283…`），只解出 `src/test/resources/data/V1997` 到 `/tmp/rea-jet3-samples`，并把该目录传给
  `REA_JACKCESS_JET3_DIR`；下载失败时用例自动不注册，构建仍然继续。本机按同一脚本预演，Jet3 四个
  用例全部执行并通过。

## 6. 风险

- **编码页**：代码页解码依赖现有 `decode_jet4_code_page` 的表，Jet3 用同一套代码页编号，但文本按列
  排序序优先，需要在 J3 明确优先级。
- **无写入**：固定版本只读，任何写路径都不必实现，也不要为 Jet3 打开写句柄。
- **样本不入库**：Jet3 用例只在有 Jackcess 检出时运行；CI 若要覆盖，需要改成按需下载上游测试资源并
  固定哈希，这一步单独评估。

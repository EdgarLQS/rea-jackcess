# 只读优先开发交接

## 接手目标

在本仓库继续实施[只读优先计划](09-只读优先实施计划.md)。首先冻结首期只读矩阵、盘点语料并复现 Jet4 读取对照，随后按缺口推进。首期范围是 Jet4 V2000/V2003 和 ACE V2007/V2010/V2016/V2019 普通库。暂停新增写入能力，PGeo 导入在核心只读放行后独立启动。

## 起始基线

- 制订计划时的起始提交为 `3dc0759`，工作树干净。macOS ARM64 临时构建的 CTest **30/30 通过**。本次未注册仅在本机存在外部 PGeo 样本时启用的 `real_sample`。原生 Linux 双架构验收仍待执行。
- Jet4 已有目录、表列定义、Usage Map、普通记录与溢出行、长值、游标、索引扫描与键查询、关系、属性及保存查询读取基础。现有回归包括自建和固定语料。独立来源的逐版本覆盖及 P1 放行待补。
- ACE V2007/V2010 有固定样本的普通表、复杂关联及类型化复杂值证据。V2010 另有计算列逻辑类型和已存结果用例。V2019 固定样本已验证扩展日期及对应计算列已存结果，历史记录还列出 `MSysResources.Data` 类型映射缺口。V2016 和额外 V2019 样本待验。
- 行为基线为 Jackcess 5.2.0、源码提交 `6159c680933625ffa952334b5e0e6b24f37bfdfe`、JAR SHA-256 `9451d6f336cfaa82f5af178d5f6668b933cda4f27e261f29a1faa83630f95775`。外部比较器和语料路径见[计划总览](README.md)。实现和历史证据入口见[原交接说明](05-交接说明.md)与[基线核验记录](04-P0基线核验记录.md)。

## 第一个工作包

1. 先检查 `git status --short` 和 `git rev-parse --short HEAD`，阅读仓库 [AGENTS](../../AGENTS.md) 与[源码架构](../../src/ARCHITECTURE.md)。接手时按实际分支更新基线记录。
2. 以[能力矩阵](03-Jackcess-5.2.0能力矩阵.md)为源，整理六个版本的首期读取验收项。每项写明入口、语料、预期行为、证据和当前状态。Jet4 读写混合项拆开评估。优先确认独立来源 Jet4、V2016、额外 V2019 语料，以及两个原生 Linux 环境是否可用。
3. 运行 CTest，再至少各选一个 V2000/V2003 样本，用 C++ `canonical` 和固定 JAR 核对用户表 schema、行数、值及长值摘要。记录样本来源和哈希、实际命令、版本与差异。若缺少真实语料或对照工具，先完成可复现的仓内回归，逐项登记缺口及后续取得途径。
4. 提交首期矩阵、样本盘点和 Jet4 基线结果作为本工作包产物。按“已通过、明确拒绝、待验证”登记结论。随后优先修复影响 Jet4 读正确性或明确拒绝行为的差异，使用对应格式的最小回归复现。

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
ctest --test-dir build -R 'database_file|catalog|cursor|saved_query|ace|attachment_value|real_sample' --output-on-failure
```

固定语料见 [fixtures 说明](../../tests/fixtures/README.md)。优先复用仓库 `tools/validation/` 和 `MDB_REFERENCE_DIR/resource/test-mdb-validation/`。保护原始输入，涉及已有写入回归时使用副本。每次汇报分别列出本机回归、固定版本对照和目标平台验收的实际覆盖。
